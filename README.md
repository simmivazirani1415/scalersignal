## 1. What I built

Scalersignal is an agent running natively on WhatsApp which supports a Scaler BDA in two critical moments. **Pre-call:** the BDA receives a concise, scannable message on their personal WhatsApp account — who the lead is in regular language, what angles would work on them (two or three), two or three possible objections with short-handling tips, and an opening hook suggestion. **Post-call:** the lead receives a 2-3-page personalised document in PDF format on their WhatsApp answering their questions, after which every single send is approved by the BDA (or edited/overlooked by them). Supports either transcript or audio — the latter gets transcribed using Google Apps Script. Tech stack: React+Tailwind on Firebase, Python on Railway, Supabase database, Twilio API to use WhatsApp, OpenAI gpt-4o-mini for generating content.

## 2. One failure

A test was performed with a single-line transcription: "Lead said they'll think about it, hung up" for all three personas. Agent generated generic versions of the PDF as there were no personalized queries in the transcript. Garbage in, garbage out. Solution is a BDA gap-filler prompt before generation.

## 3. Scale plan

At 100k leads/month (≈3,300/day), there are two issues that emerge first.

**(1) Approval bottleneck.** At 30 seconds per PDF review, 3,300 reviews mean 27 hours of work daily on approvals alone. Solution: Approve all except flagged ones (low confidence, risk of hallucinations, claims new curriculum). Approvals should be done through random sample checks automatically.

**(2) Curriculum hallucinations at scale.** When RAG is applied for scalability at scaler.com with 100k personalization requests, the slightest outdated or disputed claim gets amplified. Solution: A layer of facts managed by program owners but not generated by the LLM. The agent personalizes the framing; facts are looked up but never generated.
